# بستهٔ کامل Step 3 — Dialogue AI + Streamlit — نسخهٔ ۱٫۰٫۱

این بسته، بخش «عامل مکالمهٔ فارسی و نگهبان استخراج» پروژهٔ Rahnama Career Path Assistant را تکمیل می‌کند: تسک‌های ۱ تا ۵، قرارداد `ConversationManager`، تاکسونومی نمونه، موتور مرجع گراف، UI و تست‌های خودکار.

## شروع سریع در ویندوز

۱. ZIP را Extract کن و وارد پوشهٔ `DialogueAI_Streamlit` شو. Python 3.11 یا جدیدتر باید نصب باشد.
۲. فایل `01_setup.cmd` را اجرا کن؛ اینترنت برای نصب وابستگی‌ها لازم است. این فایل کلید یا `.env` قبلی را بازنویسی نمی‌کند.
۳. فایل `02_run.cmd` را اجرا کن.
۴. در مرورگر آدرس **http://127.0.0.1:8501** را باز کن. برنامه در حالت دموی آفلاین بالا می‌آید و API مصرف نمی‌کند.
۵. در تب گفتگو، «اجرای نمونهٔ کامل» را بزن؛ سپس تب گراف و خلاصه و تب پروفایل را نشان بده.

در macOS/Linux: `bash run.sh` نصب اولیه و اجرا را انجام می‌دهد. اجرای دستی پس از نصب: `python -m streamlit run app.py`.

## اتصال Gemini در متیس

این نسخه علاوه بر OpenAI-compatible، پروتکل native Gemini را پشتیبانی می‌کند. برای متیس، فایل `.env.metis.example` را در همان پوشه به `.env` کپی کن و کلیدت را محلی وارد کن:

```dotenv
LLM_PROTOCOL=gemini
OPENAI_API_KEY=YOUR_METIS_KEY
OPENAI_BASE_URL=https://api.metisai.ir
OPENAI_MODEL=gemini-2.5-flash-lite
LLM_RESPONSE_FORMAT=json_object
MAX_SESSION_TOKENS=30000
```

نام مدل بالا فقط مثال است: باید با شناسهٔ دقیق Flash-Lite فعال در پنل متیس خودت جایگزین شود. دسترسی حساب تو به این شناسه آزمایش نشده است. نام متغیرهای OPENAI برای سازگاری حفظ شده ولی در حالت gemini، درخواست از نوع Gemini است.

این نسخه خودش مسیر `/v1beta/models/{model}:generateContent` را به Base URL اضافه و کلید را در هدر `x-goog-api-key` ارسال می‌کند؛ آدرس کامل generateContent یا مسیر OpenAI را در Base URL نگذار. `LLM_PROTOCOL=gemini` فقط در نسخهٔ ۱٫۰٫۱ به بعد اثر دارد؛ نسخهٔ قدیمی ۱٫۰٫۰ آن را نمی‌خواند.

در UI، «API واقعی»، پروتکل «Gemini native (متیس)» و سپس «شروع / اعمال تنظیمات» را انتخاب کن. برنامه با کلید واقعی تو تست نشده؛ `python smoke_api.py` یک درخواست واقعی با دادهٔ مصنوعی می‌فرستد و هزینه دارد.

مرجع اتصال: [مستند رسمی Gemini در متیس](https://docs.metisai.ir/api/wrapper/gemini/).

## اتصال کلید API

کلیدت را در چت، Git یا فایل خروجی قرار نده. فایل `.env` کنار `app.py` را با ویرایشگر متن باز کن. نمونه:

```dotenv
OPENAI_API_KEY=YOUR_TEAM_KEY
OPENAI_BASE_URL=https://YOUR_GATEWAY/v1
OPENAI_MODEL=EXACT_MODEL_ID_FROM_GATEWAY
LLM_RESPONSE_FORMAT=json_object
MAX_SESSION_TOKENS=30000
```

در حالت `LLM_PROTOCOL=openai`، آدرس باید Base URL درگاه سازگار باشد؛ `/chat/completions` به‌وسیلهٔ برنامه اضافه می‌شود. برای Gemini متیس از بخش بالا استفاده کن. نام مدل را دقیقاً از درگاه تیم بردار. تنظیمات نمونهٔ OpenAI به‌معنای سازگاری کلید درگاه دیگر با آن نیست.

برنامه را اجرا کن، در نوار کناری «API واقعی» را انتخاب و «شروع / اعمال تنظیمات» را بزن. اگر کلید را در فیلد رمزدار UI وارد کنی، بر کلید `.env` اولویت دارد و صرفاً در حافظهٔ نشست نگه‌داری می‌شود. تغییر `.env` پس از اجرا ممکن است نیاز به بستن و اجرای مجدد سرور داشته باشد.

- `json_schema`: برای مدلی که Structured Outputs را پشتیبانی می‌کند؛ تمام کلیدها required و ساختار بسته است.
- `json_object`: برای درگاه سازگار با JSON mode؛ در Gemini native به responseMimeType=application/json نگاشت می‌شود؛ اعتبارسنجی نهایی همچنان با Pydantic و تاکسونومی انجام می‌شود.
- `prompt_json`: فقط زمانی که درگاه هیچ‌یک را ندارد؛ مدل با پرامپت JSON می‌دهد و خروجی نامعتبر رد می‌شود.
- خطای ۴۰۰ ممکن است از قالب خروجی، مدل یا پارامترها باشد. وضعیت کلید/مدل/قالب را در مستندات درگاه بررسی کن. تغییر قالب خودکار و درخواست مجدد هزینه‌دار انجام نمی‌شود.
- هر پیام حداکثر یک درخواست استخراج دارد. سؤال‌ها و خلاصهٔ گراف قطعی‌اند. تأیید نهایی و فرم دستی هیچ API مصرف نمی‌کنند.

## آنچه UI نشان می‌دهد

| بخش | کاربرد |
|---|---|
| گفت‌وگو | ارزیابی فارسی با حداکثر شش سؤال، تأیید و اصلاح متنی |
| بارگذاری رزومه | استخراج محلی متن PDF، DOCX یا TXT و عبور از همان مسیر اعتبارسنجی گفتگو |
| مسیر پیشنهادی | گراف تعاملی، ترتیب مطالعه و توضیح فارسی از همان گراف؛ خروجی JSON و متن |
| پروفایل من | بررسی اطلاعات، اصلاح دستی معتبر، ثبت «هیچ مهارتی ندارم» و تأیید نهایی |
| دربارهٔ مسیر | توضیح سادهٔ فرایند و حریم خصوصی؛ قرارداد فنی تیم در بخش جمع‌شونده |

تغییر داده‌های پروفایل، تأیید و گراف قبلی را باطل می‌کند. پس از بررسی و تأیید پروفایل تازه، گراف دوباره محاسبه می‌شود. حذفِ مهارتی که از ابتدا در دانسته‌ها نبود، تغییری در پروفایل ایجاد نمی‌کند.

## هماهنگی با تیم گراف

`data/demo_taxonomy.json` صرفاً نمونه است: ۱۲ نقش، سه حوزه و ۴۰ مفهوم. ساختار آن با `docs/taxonomy.schema.json` تعریف شده است؛ این فایل مرجع حرفه‌ای جامع یا کاتالوگ منابع آموزشی نیست.

برای استفاده از فایل تیم، تیک «تاکسونومی نمونه» را بردار، فایل JSON را بارگذاری کن یا مسیرش را وارد کن و «شروع / اعمال تنظیمات» را بزن. در فایل واقعی `is_demo` را false بگذار. نسخه، شناسه‌ها، مترادف‌ها، نیازمندی‌های سطح‌ها و پیش‌نیازها باید با قرارداد منطبق باشند. اگر فایل تیم شکل دیگری دارد، یک تبدیل صریح بنویسید؛ جایگزینی پنهانی با دادهٔ Mock انجام نمی‌شود.

به‌طور پیش‌فرض `ReferenceGraphEngine` با همین تاکسونومی کار می‌کند. برای اتصال موتور تیم، شیء دارای `build_roadmap(profile, revision)` را به آرگومان `graph_engine` بدهید. خروجی آن پیش از نمایش بررسی می‌شود؛ نمونه در `integration_example.py` و قرارداد در `docs/CONTRACTS_FA.md` است.

## نحوهٔ اجرای تست

ویندوز: `03_test.cmd`.

یا از داخل همین پوشه:

```bash
python -m unittest discover -s tests -v
```

تست‌ها بدون کلید و بدون تماس با سرویس خارجی اجرا می‌شوند. پوشش شامل سقف سؤال، پروفایل ناقص، کاربر بدون مهارت، دادهٔ ساختگی، شاهد مهارت، اصلاح پس از اتمام، خرابی تاکسونومی، چرخهٔ گراف، ترتیب مطالعه، خلاصهٔ A-09، timeout، refusal، JSON خراب، بودجه و تعامل واقعی با AppTest است. نتایج و محدودیت‌ها در `docs/VALIDATION_FA.md` آمده‌اند.

برای آزمایش اتصال واقعی با دادهٔ مصنوعی خود بسته، پس از تنظیم `.env`:

```bash
python smoke_api.py
```

این دستور **یک درخواست واقعی هزینه‌دار** به درگاه تنظیم‌شده می‌فرستد. فقط وضعیت، هشدارها و مصرف را چاپ می‌کند. خطای این تست را با کلیدِ پنهان برای بررسی نگه دار؛ کلید را به دیگران نده.

## حدود تحویل

- خلاصه‌ساز A-09 قطعی و فارسی است. فقط گره‌ها و یال‌های تأییدشدهٔ همان گراف را توضیح می‌دهد؛ مهارت، زمان یادگیری یا لینک تازه نمی‌سازد.
- در پایان سقف سؤال، پروفایل ناقص موفق اعلام نمی‌شود. اصلاح دستی/متنی پس از آن ممکن است، اما سؤال ارزیابی تازه‌ای تولید نمی‌شود.
- کنترل شاهد متنی محافظه‌کارانه است: بعضی بیان‌های پیچیده ممکن است رد شوند؛ فرم دستی راه اصلاح آن است. تطبیق شاهد و تاکسونومی به‌تنهایی تضمین فهم کامل معنای همهٔ جمله‌ها نیست.
- Mock یک پارسر محدود برای دموست. کیفیت استخراج مدل واقعی، تأخیر زیر ده ثانیه و هزینهٔ واقعی نیاز به آزمون با درگاه و مدل تیم دارند. این بسته با کلید واقعی شما اجرا نشده است.
- برای کم‌شدن تأخیر، یک تماس استخراج، timeout شبکه و بدون retry خودکار استفاده شده است. timeout شبکه، تضمین قطعی مدت کل درخواست نیست.
- توکن‌های گزارش‌شدهٔ درگاه ثبت می‌شوند. اگر usage موجود نباشد، شمارندهٔ جدا و رزرو محافظه‌کارانه برای بودجه استفاده می‌شود. هزینه فقط با نرخ‌هایی که خودت در `.env` وارد می‌کنی تخمین زده می‌شود؛ مصرف پنل درگاه مرجع نهایی است.
- داده‌ها فقط در حافظهٔ نشست‌اند و این برنامه پروفایل/متن را لاگ یا خودکار روی دیسک ذخیره نمی‌کند. دانلودها انتخاب کاربرند. برنامه را روی دستگاه مشترک بدون بستن نشست رها نکن. حالت API داده را به ارائه‌دهندهٔ انتخابی می‌فرستد.
- پس از دو ساعت بی‌فعالیتی، نشست در دسترسی بعدی پاک می‌شود. این نمونه برای اجرای محلی است؛ احراز هویت و ذخیره‌سازی چندکاربرهٔ production در دامنهٔ آن نیست.
- رزومه‌های PDF، DOCX و TXT در حافظه به متن تبدیل می‌شوند و از همان قرارداد `handle_user_turn` عبور می‌کنند؛ فایل روی دیسک ذخیره نمی‌شود. PDF اسکن‌شده بدون لایهٔ متن و فایل رمزگذاری‌شده پشتیبانی نمی‌شوند. رتبه‌بندی شغل (Module B) و منابع آموزشی تأییدشده (A-07) همچنان در حوزهٔ سایر اعضای تیم‌اند.

## فایل‌های مهم

- `app.py`: UI فارسی Streamlit.
- `dialogue/manager.py`: رابط نهایی و کنترل مکالمه.
- `dialogue/schemas.py`: مدل‌های داده و قرارداد خروجی.
- `dialogue/guardrails.py`: بارگذاری سخت‌گیرانهٔ تاکسونومی و نگاشت مترادف‌ها.
- `dialogue/llm_client.py`: اتصال HTTP به درگاه سازگار و کنترل خطا/مصرف.
- `dialogue/mock_client.py`: دموی آفلاین محدود.
- `dialogue/resume.py`: استخراج محدود و درون‌حافظه‌ای متن رزومه برای ورودی UI.
- `dialogue/graph.py`: موتور مرجع و بررسی قرارداد خروجی تیم گراف.
- `dialogue/summarizer.py`: تسک ۵، خلاصهٔ فارسی A-09.
- `docs/DEMO_FA.md`: سناریوی ارائهٔ کوتاه به تیم.
